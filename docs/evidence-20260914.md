# P2L evidence snapshot - 14 September 2026

This note records the lightweight evidence added after the 13 September code-only snapshot. It does not include manuscript files, model weights, datasets, extracted features, candidate embeddings, or large indexes.

## Frozen selection-only evaluation

The `vldb_p0_fixed_score_eval12_20260914` campaign evaluates the twelve M-BEIR configurations that were not used for execution-policy selection.

Frozen-Levelwise and Frozen-P2L share the masked checkpoint, depth-three prefix setup, candidate semantic-ID index, Independent-Suffix position-wise score tables, complete-key scoring rule, reranker, deterministic tie rule, `B=K=50`, `s=3`, and `lambda=0`. The changed factor is the intermediate legal top-B selection schedule.

Headline task-macro results:

- R@10: 38.46% -> 42.10% (+3.64 percentage points; paired-query 95% CI [3.42, 3.86]).
- IDR@50: 42.67% -> 47.12% (+4.46 percentage points).
- R@10 point estimates: 12/12 positive; 11/12 task intervals exclude zero.
- Evaluation queries: 178,587.
- APF (avoidable pruning failure): 7.63% task macro. APF is a failure-mode diagnostic, not an additive decomposition of the R@10 gain.

The CSV also records relevant-frontier survival, generation/retrieval timing, and exposed-frontier statistics for each task. The summary JSON records campaign provenance, bootstrap settings, hardware, and SHA256 hashes for the checkpoint, quantizer, runner, and source bundle.

## Evaluation groups

`evaluation_groups_20260914.csv` records the disjoint Development-4 and Evaluation-only-12 groups plus the descriptive All-16 aggregate. The evaluation-only group is the primary cross-configuration result outside policy selection; it was not held out from model training.

## Lightweight verification

```bash
python scripts/structnar/audit_fixed_score_eval12.py
```

The script uses only the bundled CSV/JSON files and checks the task macro, query count, positive-task count, task-interval count, APF, and key timing/frontier summary values.

## Scope

The public repository remains a source-and-lightweight-evidence artifact. Full reproduction still requires the licensed M-BEIR assets, frozen retrieval/RQ assets, the evaluated checkpoint, and the realized candidate semantic-ID/Trie files.
