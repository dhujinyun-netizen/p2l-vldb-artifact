01 / Overview

When should a partial identifier be pruned?

Semantic-ID retrieval generates structured keys constrained by a Trie index. Sequential beam search prunes partial keys after each position, before evidence from the remaining codes is available. A relevant item can therefore be discarded before its complete identifier is scored.

Prefix-to-Leaf (P2L) retains a short prefix, enumerates its stored descendants, and ranks complete identifiers using shared suffix scores. The default realization conditions each unresolved position on the query and retained prefix, without cross-position suffix attention. It changes the post-localization selection schedule while reusing the frozen checkpoint and candidate index.

On the twelve configurations excluded from policy selection, macro R@10 increases from 38.81% to 42.10% (+3.29 points; 95% CI [3.07, 3.52]). The all-16 value, 39.36% → 43.64%, is reported only as a descriptive aggregate.

02 / Method

Search the prefix. Score the complete leaves.

The semantic-ID index separates routing from candidate refinement. P2L uses this structure to share neural suffix prediction across the descendants of each retained prefix.

  1. Retain a short prefix

    Trie-constrained search localizes the query to a set of prefixes. The default switch depth is s = 3, including the modality-routing code.

  2. Share suffix prediction

    Enumerate stored descendants and score unresolved positions in one suffix round. Each position attends to the query and prefix, independently of other suffix positions.

  3. Select complete identifiers

    Aggregate prefix and suffix scores, then select the top 50 complete IDs across the retained frontier. Exact-ID expansion and embedding reranking are reused.

Selection is exact within the enumerated frontier, not over the full index. P2L cannot recover a leaf whose prefix was already pruned. The current default uses B = K = 50 and λ = 0.

03 / Positioning

A different answer to early commitment

Recent methods address early identifier errors by improving prefix evidence or relaxing uncertain expansion. WIDE, for example, emits wildcard identifiers at uncertain suffix positions and reranks the compatible candidates with hybrid evidence.

P2L makes a different execution choice: it fixes a prefix-localization boundary, enumerates the stored complete descendants below that boundary, and postpones partial-key selection until complete-key scores are available. WIDE and P2L are therefore complementary rather than interchangeable baselines; this page summarizes the conceptual distinction and does not claim a matched WIDE reimplementation.

06 / Qualitative mechanism

The same prefix frontier, different commitment point

These four fixed cases connect the final item ranks to the semantic-ID search trace. In the first three, the relevant prefix survives at s = 3, is later pruned by Sequential, and remains available to P2L for complete-key scoring. Fashion200K-0 is a boundary case: both policies retain the relevant path, while P2L changes its final ordering.

07 / Case analysis

Additional CIRR examples

Two previously illustrated CIRR-7 queries show both outcomes under the current matched Sequential and Independent-Suffix P2L configurations (λ = 0). Each comparison displays the query, annotated target, and the actual top-ranked item returned by each method.

Case A / Recovery · query 8:17

“Dog with human instead of another dog.”

Target rank >10 → 1

Reading the result. P2L places the annotated target first, while Sequential does not return it in the saved top 10. Both top-1 images contain a dog and a person: the distinction is recovery of the annotated target, not simply recognition of the requested human presence.

Case B / Failure · query 8:1053

“The target shows one panda with one hand on his mouth.”

Target rank 1 → >10

Reading the result. P2L returns the correct animal category but misses the requested hand-to-mouth pose. Sequential retrieves the annotated target first. This example illustrates a fine-grained mismatch and shows why aggregate improvement does not imply per-query dominance.

These are selected examples, not a random sample. The same two previously illustrated query IDs were rechecked using the current λ = 0 runs, which reproduce CIRR-7 R@10 of 42.16% and 45.35% over 4,170 queries. “>10” means absent from the saved top-10 list, not a measured rank beyond it. Final rankings do not isolate whether a change arose during prefix search, suffix scoring, or reranking. Images are CIRR/M-BEIR examples and remain subject to the source dataset’s terms.
