# P2L project-page evidence — 16 September 2026

This page follows the manuscript package `P2L_VLDB_title_WIDE_positioning_20260916.zip`.
The website presents a lightweight method overview and evidence summary; it does
not redistribute the manuscript, supplementary PDF, model checkpoint, datasets,
or large semantic-ID indexes.

## Current policy

The evaluated policy is Independent-Suffix P2L with switch depth `s=3`,
prefix/output widths `B=K=50`, `lambda=0`, inference guidance `omega=3`, and
the epoch-99 frozen checkpoint. Sequential and P2L share the checkpoint,
semantic-ID index, query/candidate realization, and downstream reranker.
P2L changes the post-localization selection schedule; Independent-Suffix is the
shared suffix-scoring realization used by the masked retriever.

## Effectiveness evidence

| Comparison | Scope | Reported result |
|---|---|---|
| Sequential → P2L, uniform R@10 | 12 evaluation-only configurations | Macro 38.81% → 42.10%; **+3.29 points**; paired-query 95% CI [3.07, 3.52] |
| Frozen-Levelwise → Frozen-P2L, fixed score rule | 12 evaluation-only configurations | Macro 38.46% → 42.10%; **+3.64 points**; 95% CI [3.42, 3.86]; IDR@50 +4.46 points |
| Development-4, uniform R@10 | CIRR-7, NIGHTS-4, EDIS-2, WebQA-1 | Macro 40.99% → 48.24%; +7.24 points; 95% CI [6.50, 7.97] |
| All-16 descriptive aggregate | 16 LOCAL configurations | Macro 39.36% → 43.64%; +4.28 points; 95% CI [4.03, 4.53] |
| Benchmark-designated cutoffs | Fashion200K/FashionIQ R@10; other tasks R@5 | Macro 35.46% → 39.20%; +3.73 points |

The evaluation-only group was excluded from P2L policy selection according to
the reported development chronology. It is not a claim of twelve independent
datasets or unseen training domains. The all-16 value is descriptive and is not
added to the fixed-score control gain.

## Execution and scale evidence

* Five repeated batch-1 runs on four representative workloads reduce
  identifier-generation latency by 41.6–42.3% and decode-to-rerank latency by
  39.4–40.0%; the timing starts from cached query embeddings.
* On a 5,609,079-item UNION pool, R@10 gains are +3.19 points (CIRR-7) and
  +9.69 points (EDIS-2); generation latency decreases by 48.7% and 46.1%.
* The nested CIRR measurements cover 21K–1M items under the current `lambda=0`
  policy; the existing 5.61M endpoint is shown descriptively and is not used to
  claim collection-independent complexity.
* The exact chunked top-K audit returns the same ordered keys, scores, and R@10
  as full materialization for Evaluation-only-12 at chunk sizes 4096, 16384,
  and 65536. The current Python streaming path is approximately 11% slower;
  this establishes correctness and bounded buffering, not a speedup claim.

## WIDE positioning

WIDE and P2L address related early-commit risks with different execution
choices. WIDE emits wildcard identifiers at uncertain suffix positions and
uses hybrid evidence to expand and rerank compatible candidates. P2L keeps a
fixed depth-three localization boundary, enumerates stored complete descendants,
and performs global complete-key selection with prefix-shared suffix scores.
The website describes this conceptual distinction; it does not claim a matched
WIDE reimplementation.

## Qualitative evidence

The four-panel mechanism figure uses fixed cases from the current run records:
WebQA-2, VisualNews-3, FashionIQ-7, and Fashion200K-0. The first three show a
relevant prefix surviving at `s=3`, later pruning under Sequential, and a
complete-key rank under P2L. Fashion200K-0 is a boundary case in which the
relevant path survives both policies and the final rank changes from 3 to 2.
These examples explain mechanism heterogeneity and are not an estimate of
outcome frequencies.
